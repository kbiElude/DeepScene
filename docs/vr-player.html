The window

The window has a list on the left and a pane on the right.

PartContent
Left listThe catalog programs, alphabetically by name. A card shows the title (the catalog writes it as name by group (year)), the description if the recipe has one, and the reason when the program cannot be launched. A title longer than the card wraps.
Right paneThe title, the reason if the program is unavailable, the description if there is one, the VR settings and, at the bottom, the Launch button (it says Download & launch while the program is not on the computer, and Cancel while a download runs).
Above the buttonThe download progress, or an error in a table, or the hint Pick an application which is available. when nothing can be launched.
Catalog problemsThe list says The catalog cannot be read with the reason, or that it lists no applications. With no apps.json to be found it says to use --catalog.

SettingStart value

DepthNatural.

The first launch

The button of a program that is not on the computer says Download & launch. It starts the download, and the program then starts by itself. The next launches say Launch and start it at once.

PartDetail
ProgressAbove the button: the program, the step and the bytes (x MB of y MB). The button is Cancel meanwhile.
AddressesThe catalog's addresses, all https, one after the other. The window names the host it is using.
CheckThe hash of the zip file must be the catalog's, and the unpacked files may not take more than its unpacked_size.
StagingEverything is written to apps\<id>.download\ and moved to apps\<id>\ when complete, so an interrupted install leaves nothing that looks installed. One install of a folder runs at a time, even across several DeepScene processes.

When it fails

A window titled Cannot install the application says what. The status above the button says The application cannot be installed.

CauseWhat the window says
No address worksThe error of each host, and the page of the catalog entry to download the program by hand.
The file is not the expected oneThat the download was not used.
A folder that cannot be written toTo move DeepScene to a place that can be written to.
apps\<id>\ exists, is not empty and has no programTo remove the folder and launch again.
The program is missing after the unpackingThat a virus scanner may have removed it, and to look in its quarantine.

A launch that fails is reported in a table above the Launch button.

The launch sequence

AppSession::start() does the following, in this order. The order is the reason for each step.

RuleReason
The window (presenter) comes before the launcher.It is there when the first image arrives.
The two helpers are suspended until they are in the job.A process that starts another before that would leave one outside the job.
The launcher's output goes to a pipe.The pipe keeps what the launcher says, so the window can show why a program stopped (when the launcher exits with a code other than 0).
The eye size is always written: the one chosen as Resolution per eye (a fraction of the headset size, or a size), else 0 x 0.Any size says the window of the presenter shows the program, so the converter makes the program's own window invisible (Direct3D 7 and OpenGL as well as Direct3D 8). 0 x 0 keeps the size the program asks for. It is limited to 4096 x 4096 for an eye, the size of the channel.

The session id is the process id of VRPlayer, a dash and a tick count. It names the frame channel, and the log.

How a session ends

What happensResult in the window
The program exits and the launcher returns 0The session ends, nothing is said.
The launcher returns another code (a recipe that cannot be used, a program that cannot be started, a converter that stops the program)What the launcher printed, in the table above the button.
The window of the presenter is closed, or the user takes the program out of the headset, or the runtime ends the sessionThe session ends, and the job takes the launcher and the program with it.

Pieces

PieceRole
VRPlayerThe window; reads the catalog and starts a session (AppSession).
StereoLauncherStarts the program suspended and injects the converter DLL.
Program + StereoConverterDLLThe program, with the converter that makes both eyes inside it.
StereoPresenterReceives the frames through the channel and sends them to a sink: the preview window or the headset. It is 64-bit whatever the program is, because it talks to the VR runtime.
Frame channelShared memory with room for three images of at most 8192 x 4096 (two eyes of 4096 each). The converter writes and never waits for the reader; the reader sees the newest image, never one being written. Whichever side opens it first creates it.

Frame number and time

While the headset shows the images, the window reads Showing in the headset (no preview while it does) and, once a frame has been shown, Frame N t = S s.

NumberMeaning
Frame NThe presents of the application, counted from 0 by the converter, as the replay counts frames.
tSeconds since the converter started, which is about the first call of the application. It is close to the times of the analysis timelines for a run of the same program, but not equal, since the two runs differ in what they wait for.

Both travel with each frame through the channel, so a glitch can be named by frame and time.

Controls

ControlWhat it does
DeviceThe output: a headset found through OpenXR, or the preview window alone (2D preview only).
DepthReduced, Natural or More: a strength of 0.65, 1.0 or 1.25 that scales the eye separation of each scene. The comfort limit of the recipe is a ceiling that More does not pass, unless the recipe lets the limits follow the strength (limits_follow_strength). It can be changed while the program runs.
Resolution per eyeThe size each eye is rendered at: a fraction of the headset size (disabled when there is no headset), one of 1280 x 720 to 3840 x 2160, or a size that is typed in (up to 4096 on a side). The program keeps its proportions, centered in the image, and what does not fill it is black. It works for all three APIs and is set when the program starts.

The last two are for a graphics card that cannot keep up.

Without a control

WhatHow it is set
2D overlaysPushed toward the viewer by the amount the recipe gives (comfort.overlay_parallax) for a program whose recipe has one.
PacingWith a headset the program makes one frame for each frame of the headset. VRPlayer always asks for it; StereoPresenter --headset --no-pacing, started by hand, turns it off.
LogNone is written unless VRPlayer is started with --log (an option of the programs it starts too).
Distance between the eyesWith a headset: read from OpenXR while the program runs; its ratio to 64 mm (limited to 0.7 to 1.4) scales the separation, so a narrow or wide IPD is followed.

Headset path

  1. The presenter maps the frame channel and the uploader opens its memory as a D3D12 heap (at the allocation base of the mapped view; a pointer inside the view does not work) and places a cross-adapter buffer over it.
  2. A thread of the headset sink takes the newest frame from the channel about every millisecond, so that nothing which waits for the screen of the PC (a window that is drawn once a refresh) sets its pace.
  3. The images of a swap chain hold whatever was in the memory when it is made, which flickers (a stroboscope effect while the application loads). So the session makes the swap chains of the recommended eye size as soon as it runs, every image is cleared to black on the GPU (D3D12TextureClearer of Utils), and black is shown from the start.
  4. If the frames of the application are of another size, the swap chains are made again and cleared again, so that no image is ever shown that nothing was written to.
  5. For each new frame, each eye is copied from the buffer (a source box per eye, footprint offset = pixel pointer minus base) into the eye's OpenXR swapchain image.
  6. The screen is a world-locked quad, or a cylinder if the runtime supports XR_KHR_composition_layer_cylinder, two metres away and sized to fill about 92% of the shared field of view. One layer per eye with eyeVisibility.
  7. A recenter action puts the screen in front of the viewer again: on Touch controllers the left menu button or the right A button, on a simple controller the menu button of either hand.
  8. The headset's own session ends when the user takes the program out of the headset or the runtime ends it. The presenter then closes its window, which ends the session (How a session ends).

Devices

The device dropdown is filled by OpenXrVrDeviceProvider, which asks the OpenXR runtime for its headset once, when VRPlayer starts.

SituationThe dropdown
No OpenXR runtime or headsetShows only 2D preview only and is disabled, with a line saying that the picture is shown in the window only; Launch works.
A headsetThe headset by the name the runtime gives it, selected, with the runtime's name below; 2D preview only is the last entry of the list.
A device that has an unavailable reasonListed as (unavailable), with the reason as a tooltip. The OpenXR provider sets none: it lists one device or none.
Windows: the active OpenXR runtime must be set in the vendor's software (for a Quest, Meta Quest Link). If the registry names a runtime that is not installed, the loader finds none and the presenter logs “The headset is not used” and keeps showing frames in the window.

Logs

With --log on StereoLauncher, or on VRPlayer (which passes it on to both programs), a session writes %TEMP%\apistereo_<session>.log; without it, only what stops the application or the headset is written. Lines ending in “(presenter)” come from the headset path.

Each second the log has three lines of timings, in milliseconds, each as n= (count), mean=, worst= and late=. They tell where a stutter comes from.

LineWritten byWhat it times
Pacingthe converterThe presents of the program, the frames passed on, what the copies cost, the wait for the screen.
Frames to the headsetthe presenterWhen the frames arrive, taking the images, the copy to them, how far into a frame the images are ready, the delay of the pace.
Frames of the compositorthe presenterThe frames of the headset, the waits in them, and how many showed new images, repeated ones, none or were skipped (new, repeated, empty, skipped).
