The window

The window has a list on the left and a pane on the right.

PartContent
Left listThe catalog programs, alphabetically by name. A card shows the name, the description, and the reason when the program cannot be launched.
Right paneThe name, the reason if the program is unavailable, the download size if it has to be downloaded, the description, the VR settings and, at the bottom, the Launch button (Cancel while a download runs).
Above the buttonThe download progress, or an error in a table, or the hint Pick an application which is available. when nothing can be launched.

Starting it

VRPlayer.exe [--catalog file.json] [--log]
ItemBehaviour
CatalogWithout --catalog, the first apps.json found next to VRPlayer.exe, in an apps\ next to it, or in the apps\ of the folder above. A catalog that cannot be read is shown in the window, with the reason.
Unavailable entriesAn entry whose recipe cannot be found or is not valid, whose program cannot be found (and which has no download), or which says unavailable_reason, is listed with the reason and cannot be launched.
Programs it startsStereoLauncher_x86.exe or _x64 by the architecture of the application, and StereoPresenter_x64.exe. They are looked for in runtime\ beside it, and beside it when there is no such folder.
--logPassed on to both; see Logs.

The first launch

The right pane says of a program that is not on the computer that it is downloaded the first time it is launched, with the size. Launch starts the download and the program then starts by itself. The next launches start it at once.

  • The window shows the progress, with a button to cancel.
  • If the download or the installation fails (the network, a file which is not the expected one, a folder which cannot be written to, a virus scanner which removes the program), a window says what, and nothing is left half done.
  • A launch that fails is reported in a table above the Launch button.

The launch sequence

AppSession::start() does the following, in this order. The order is the reason for each step.

RuleReason
The window (presenter) comes before the launcher.It is there when the first image arrives.
The two helpers are suspended until they are in the job.A process that starts another before that would leave one outside the job.
The launcher's output goes to a pipe.The pipe keeps what the launcher says, so the window can show why a program stopped.

Frame number and time

While the headset is shown, the window says Frame N (the presents of the application, counted from 0 by the converter, as the replay counts frames) and t (seconds since the converter started, which is about the first call of the application). They travel with each frame through the channel, so a glitch can be named by frame and time. t is close to the times of the analysis timelines for a run of the same program, but not equal, since the two runs differ in what they wait for.

Controls

ControlWhat it does
DeviceThe output: a headset found through OpenXR, or the preview window alone.
DepthReduced, Natural or More: a strength that scales the eye separation of each scene. The comfort limit of the recipe is a ceiling that no choice passes. It can be changed while the program runs.
Image qualityFull (the resolution of the headset, from OpenXR, with the proportions of the program), Half of the pixels and A quarter of the pixels; the last two are for a graphics card that cannot keep up. Set when the program starts; no effect without a headset.

Headset path

  1. The presenter maps the frame channel and the uploader opens its memory as a D3D12 heap (at the allocation base of the mapped view; a pointer inside the view does not work) and places a cross-adapter buffer over it.
  2. A thread of the headset sink takes the newest frame from the channel about every millisecond, so that nothing which waits for the screen of the PC (a window that is drawn once a refresh) sets its pace.
  3. The images of a swap chain hold whatever was in the memory when it is made, which flickers (a stroboscope effect while the application loads). So the session makes the swap chains of the recommended eye size as soon as it runs, every image is cleared to black on the GPU (D3D12TextureClearer of Utils), and black is shown from the start; if the frames of the application are of another size the swap chains are made again, and cleared again, so that no image is ever shown that nothing was written to.
  4. For each new frame, each eye is copied from the buffer (a source box per eye, footprint offset = pixel pointer minus base) into the eye's OpenXR swapchain image.
  5. The screen is a world-locked quad, or a cylinder if the runtime supports XR_KHR_composition_layer_cylinder, two metres away and sized to fill about 92% of the shared field of view. One layer per eye with eyeVisibility.
  6. A recenter action puts the screen in front of the viewer again.

Devices

The device dropdown is filled by OpenXrVrDeviceProvider.

SituationThe dropdown
No OpenXR runtime or headsetShows only 2D preview only and is disabled; Launch works.
A headset2D preview only is the last entry of the list.
A device that cannot be usedListed as (unavailable), with the reason as a tooltip.
Windows: the active OpenXR runtime must be set in the vendor's software (for a Quest, Meta Quest Link). If the registry names a runtime that is not installed, the loader finds none and the presenter logs “The headset is not used” and keeps showing frames in the window.

Logs

With --log on StereoLauncher, or on VRPlayer (which passes it on to both programs), a session writes %TEMP%\apistereo_<session>.log; without it, only what stops the application or the headset is written. Lines ending in “(presenter)” come from the headset path.

Each second the log has three lines of timings, in milliseconds, as count, mean, worst and how many were late. They tell where a stutter comes from.

LineWritten byWhat it times
Pacingthe converterThe presents of the program, the frames passed on, what the copies cost, the wait for the screen.
Frames to the headsetthe presenterWhen the frames arrive, taking the images, the copy to them, how far into a frame the images are ready, the delay of the pace.
Frames of the compositorthe presenterThe frames of the headset, and how many showed new images, repeated ones or none.
