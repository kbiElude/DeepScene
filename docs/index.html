DeepScene

Turns a plain 3D Windows program into stereo 3D, live, on a monitor or in a VR headset, without its source code and without changing it. These pages are for someone who is going to work on the project: they assume you know C++ and graphics APIs, and explain what is specific to this codebase.

The idea

A 3D program draws every frame once, from one camera. For stereo, the part of the frame that is a 3D scene has to be drawn twice, from two cameras a little apart, while what is flat (a menu, text, a full-screen fade) is drawn once. The program cannot be asked to do that, and its source is not there. So DeepScene works from outside, in three steps:

What the converter does to a frame

A converter is a DLL that is injected into the program. It sits on the calls the program makes to its graphics API, and for each draw it asks the recipe whether the draw is scene or interface. A scene draw is made for each eye, with a camera moved half the eye separation to each side; an interface draw is made once. The two finished images go to another process, which shows them.

The hard parts are therefore two. Telling scene from interface without the program's help, in a way that works while the program runs, and giving the two pictures the right parallax, so that the result is comfortable to look at.

Words used on these pages

WordMeaning
WorkloadThe file of every API call a program made, with the data they refer to, written by the dumper of API Interceptor.
FrameThe calls up to a present (or a flip). Every present is a frame.
PassDraws that render into the same targets in one go.
Draw signatureA 64-bit key that says what a draw is at the moment it is issued: the one thing a converter inside a running program can know of a draw (Keys).
Frame shapeThe kinds of passes a frame is made of. A capture of a demo has hundreds of thousands of frames and a few dozen shapes.
RecipeA JSON file that says how to treat each draw of one program: scene or interface, and the numbers that go with it (Recipes).
Eye separationThe distance between the two cameras, in the units of the program's camera.
Convergence distanceThe distance from the camera at which the pictures of the two eyes coincide. What is there appears at the screen; nearer things stand out of it, farther ones lie behind it.
ParallaxHow far apart the same point is in the two pictures. It is zero at the convergence distance.
Front endThe part of the analysis that follows the state of one graphics API and says what its calls mean.
AdapterThe part of the converter that knows one graphics API.
TwinA copy of a render target, depth buffer or texture that the converter keeps for the second eye.

What is supported

The code is arranged for more than one API. What depends on an API is exactly the row of this table; everything else (the model of the analysis, the keys, the recipe format, the decisions of the stereo core, the frame channel, the presenter and the player) does not know which API a program uses.

Adding an API means adding its row: see Adding an API. The converter handles Direct3D 8 programs whose camera is set with SetTransform, and Direct3D 7 programs whose vertices are already in pixels. The programs are 32-bit, as the supported applications are; the player and the presenter are 64-bit. Only the Oculus Quest 3 has been tested as a headset.
