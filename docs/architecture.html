Architecture

Three layers: the submodule that captures and replays calls, five libraries, and the programs built from them. This page is the map; Components describes each project.

The layers

The libraries and one rule

LibraryWhat it is forIts parts
utilsWhat no other library owns and any may use.images, binary_io, json, command_line, hashing, parallel, statistics, files, ui_host, d3d12
analysisTurns a workload into a model and the model into a recipe; also reads and applies recipes.api_dump_analysis (with the front ends), api_dump_dependencies, api_dump_slicing, recipe
stereoWhat the converter decides and what it hands on, whatever the API is.core, D3D7, session, transport
headsetShows the images in a headset.d3d12, xr, vr_devices
vr_playerWhat the VR player is made of besides the window and the headset.app_catalog, app_installer

A part is a folder and a namespace of its library: src/libs/analysis/recipe is Analysis::Recipe. Headers sit beside their sources; an include names the library from src/libs (#include "stereo/core/stereo_core.h").

Source tree and release

The tree of the source is the tree of the release: a program is in a folder of the name of its file, in the folder its file installs to, and a test checks it. Folders are lower-case with underscores; executables keep their product names and carry their architecture.

The processes of a live session

The launcher and the converter match the bitness of the application (the supported applications are 32-bit); everything that touches the headset is 64-bit. That is why most projects are built for both and the release has an _x86 and an _x64 file of each. See Live conversion.
